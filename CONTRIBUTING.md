# Contributing Guide

Спасибо за вклад в проект MTGA.

Этот документ предназначен для участников сообщества и описывает полный процесс — от подготовки окружения до отправки PR.

## Перед началом

- Все изменения (функции/исправления) вносятся через Pull Request.
- Целевая ветка PR должна быть `dev`.
- Держите изменения сфокусированными: один PR решает одну задачу или один тип требований.
- Не коммитьте артефакты сборки и локальные каталоги окружения (например `node_modules/`, `src-tauri/target/`, `dist/`, `.venv/`).

## Подготовка окружения разработки

### Необходимые инструменты

- Node.js (см. ограничение `engines.node` в `package.json`)
- pnpm
- uv (зависимости и запуск Python)
- Rust toolchain (для `src-tauri/`)

### Инициализация зависимостей

```bash
pnpm i
uv sync --project python-src
```

### Ограничения запуска Python

- Когда нужно запустить Python, всегда используйте `uv run ...`.
- Не используйте напрямую `python ...`.

## Рекомендуемый Git-процесс (git-flow-next)

Проект рекомендует [git-flow-next](https://github.com/gittower/git-flow-next) для стандартизированного управления ветками и релизами.

### Установка git-flow-next

- Linux/macOS:

```bash
brew install gittower/tap/git-flow-next
```

- Windows:
  1. Скачайте исполняемый файл со страницы Release git-flow-next.
  2. Поместите его в удобный каталог.
  3. Добавьте этот каталог в `PATH`.

### Инициализация

В корне репозитория выполните:

```bash
pnpm gitflow:setup
```

После инициализации остальные операции в целом следуют официальным правилам git-flow-next.

## Правила веток и коммитов

### Сообщения коммитов

Сообщения коммитов следуют Conventional Commits, например:

- `feat: add xxx`
- `fix: resolve xxx`
- `chore: update xxx`
- `feat(tauri): add xxx`

## Локальная разработка и самопроверка

### Частые команды разработки

```bash
# Запуск dev-серверов фронтенда и бэкенда (по умолчанию `http://localhost:3000`)
pnpm dev:all

# Запуск нативного dev-окружения Tauri для проверки нативного поведения; сначала установите python-бэкенд
pnpm pytauri:install:{платформа: win/mac}
pnpm tauri:dev
```

### Проверки качества по типу изменений

- Изменения Python:

```bash
pnpm py:check
```

- Изменения YAML:

```bash
pnpm eslint . --fix
```

- Изменения Rust:

```bash
pnpm rs:check
```

- Изменения JS/TS/Vue:

```bash
pnpm app:check
```

## Правила Pull Request

При отправке PR убедитесь, что:

1. Целевая ветка — `dev`.
2. Чётко описаны цель изменений, область влияния и способ проверки.
3. К изменениям UI приложены скриншоты.
4. При изменениях `src-tauri/tauri.conf.json` или `src-tauri/capabilities/` описано влияние на разрешения.

## Процессы только для мейнтейнеров

- `release:push` используется только мейнтейнерами для финального релиза.
- Разработчикам сообщества эту команду выполнять не нужно.

## Частые вопросы

### Почему PR помечен как имеющий неверную целевую ветку?

Правила репозитория требуют, чтобы целевой веткой PR была `dev`. Измените base branch вашего PR на `dev`.

### Локально всё проходит, а CI падает — что делать?

1. Сначала убедитесь, что выполнили проверочные команды, соответствующие типу изменений.
2. Затем по логам CI определите различия платформы или окружения.
3. Если проблема связана с Tauri/Rust, в первую очередь смотрите конфигурацию и логи сборки в `src-tauri/`.
