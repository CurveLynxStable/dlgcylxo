# MTGA v2.6.0 — поддержка провайдеров

## Назначение

`v2.6.0` вводит встроенный в проект слой исполнения MLiteLLM; нижестоящий интерфейс единообразно предоставляет **OpenAI Chat Completions API**.

- При настройке модели во фронтенде тип апстрима явно объявляется полем `Провайдер`.
- `/models` по-прежнему возвращается локальным прокси MTGA с текущими сопоставленными моделями; внутренние объекты MLiteLLM напрямую не раскрываются.
- Сбор системных промптов и цепочка инкрементального переопределения действуют на нижестоящие `messages`; если апстрим использует `openai_response`, MTGA на уровне прокси преобразует их в `input`, требуемый Responses.

## Правила выбора провайдера

MTGA больше не определяет провайдера по префиксу имени модели или домену `API URL` — используется непосредственно поле `Провайдер` в группе конфигурации.

Поддерживаемые значения:

- `openai_chat_completion`
- `openai_response`
- `anthropic`
- `gemini`

Старые конфигурации со значением `openai` автоматически трактуются как `openai_chat_completion`.

## Сопоставление полей конфигурации с MLiteLLM

| Поле конфигурации MTGA     | Параметр вызова MLiteLLM                | Описание                                                                                                                  |
| -------------------------- | --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `Провайдер`                | `custom_llm_provider` / тип API запроса | Определяет, вызывает ли MTGA апстрим `/chat/completions` или `/responses`, и какой адаптер провайдера использует MLiteLLM |
| `API URL`                  | `base_url`                              | Передаётся в MLiteLLM как базовый адрес апстрима                                                                          |
| `Фактический ID модели`    | `model`                                 | Для обоих OpenAI-провайдеров значение сохраняется как есть; для Anthropic / Gemini собирается `provider/model_id`         |
| `API Key`                  | `api_key`                               | Приоритет у ключа из группы конфигурации                                                                                  |
| `Промежуточный маршрут`    | префикс базового пути апстрима          | Пути `chat` и `models` строятся раздельно; для Gemini без явного значения по умолчанию используется `/v1beta`             |
| `Сопоставленный ID модели` | напрямую в MLiteLLM не передаётся       | Остаётся стабильным именем модели, публикуемым MTGA наружу                                                                |

## Текущий минимальный объём поддержки

### OpenAI Chat Completion

- `Провайдер`: `openai_chat_completion`
- Апстрим вызывается в семантике Chat Completions.
- Нижестоящий интерфейс MTGA напрямую выдаёт Chat Completions JSON / SSE.
- `Промежуточный маршрут` автоматически добавляется к `base_url`.

### OpenAI Response

- `Провайдер`: `openai_response`
- Апстрим вызывается напрямую в семантике Responses API.
- MTGA преобразует нижестоящий запрос `messages` в Responses `input`, а результат апстрима — обратно в Chat Completions JSON / SSE.
- `Промежуточный маршрут` автоматически добавляется к `base_url`.

### Anthropic

- `Провайдер`: `anthropic`
- Рекомендуемый `API URL`: `https://api.anthropic.com`
- Рекомендуемый `Фактический ID модели`: `claude-...`
- `Промежуточный маршрут` по умолчанию: `/v1`
- К базовому пути фактического запроса добавляется `/messages`

### Gemini

- `Провайдер`: `gemini`
- Рекомендуемый `API URL`: `https://generativelanguage.googleapis.com`
- Рекомендуемый `Фактический ID модели`: `gemini-...`
- `Промежуточный маршрут` по умолчанию: `/v1beta`
- К базовому пути фактического запроса добавляется `/models/{model}:generateContent`

## Семантика потокового и непотокового режимов

- Если клиент запрашивает поток и провайдер апстрима работает через Chat Completions, MTGA выполняет потоковый вызов в MLiteLLM и выдаёт вниз Chat Completions SSE.
- Если клиент запрашивает непотоковый режим, MTGA возвращает обычный Chat Completions JSON.
- Если провайдер апстрима — `openai_response`, либо конфигурация времени выполнения принудительно задаёт `stream=false`, MTGA получает финальный результат и эмулирует Chat Completions SSE на стороне прокси, затем возвращает его клиенту.

## Известные ограничения

- Текущая версия решает только мульти-провайдерную пересылку в режиме «единственного текущего сопоставления»; не включает несколько публикуемых моделей, фейловер, панель управления прокси и новую схему конфигурации.

## Рекомендуемые примеры конфигурации

### OpenAI Chat Completion

```yaml
provider: openai_chat_completion
api_url: https://example.com
model_id: gpt-4o-mini
api_key: sk-...
middle_route: /v1
```

### OpenAI Response

```yaml
provider: openai_response
api_url: https://api.openai.com
model_id: gpt-5
api_key: sk-...
middle_route: /v1
```

### Anthropic

```yaml
provider: anthropic
api_url: https://api.anthropic.com
model_id: claude-3-7-sonnet-latest
api_key: sk-ant-...
middle_route: /v1
```

### Gemini

```yaml
provider: gemini
api_url: https://generativelanguage.googleapis.com
model_id: gemini-2.5-pro
api_key: AIza...
middle_route: /v1beta
```
